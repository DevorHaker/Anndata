# 19 — FILE & DOCUMENT STORAGE ARCHITECTURE

## SmartProcure: Object Storage Abstraction, Security Controls, and Signed URL Flow

---

## 1. Storage Policy Mandates

1. **No Binary Files in PostgreSQL**: Large binary files (scanned farmer identity documents, land registry PDFs, quality photos) **MUST NEVER** be stored directly in PostgreSQL database columns as `BYTEA` or `BLOB`.
2. **Object Storage Backend**: Files reside in an S3-compatible Object Storage service (AWS S3 in production, MinIO for local Docker development).
3. **Private Buckets by Default**: Storage buckets are strictly **PRIVATE**. Public read permissions are disabled.
4. **Pre-Signed URL Access**: Frontend clients upload and download documents exclusively via short-lived, pre-signed S3 URLs generated by the API server.

---

## 2. Document Upload Data Flow

```
[Client UI]                            [API Server (Express)]                     [AWS S3 / MinIO]
     │                                           │                                         │
     │─── 1. POST /api/v1/farmers/docs/presign ─>│                                         │
     │    { fileName, mimeType, fileSize }       │─── 2. Validate MIME & Size              │
     │                                           │─── 3. Generate Storage Key (UUID)       │
     │                                           │─── 4. AWS SDK `getSignedUrlPromise`────>│ Generate PUT URL (TTL 15m)
     │<── 5. Return Pre-Signed Upload URL ───────│                                         │
     │    { uploadUrl, fileKey }                 │                                         │
     │                                           │                                         │
     │─── 6. Direct Binary HTTP PUT Upload ───────────────────────────────────────────────>│
     │    Header: Content-Type: application/pdf                                            │ Store binary file under
     │                                                                                     │ `fileKey`
     │<── 7. HTTP 200 OK Upload Confirmed ─────────────────────────────────────────────────│
     │                                           │                                         │
     │─── 8. POST /api/v1/farmers/docs/confirm ──>│                                         │
     │    { fileKey, documentType }              │─── 9. Record File Metadata in DB ───────>│ INSERT INTO farmer_documents
     │<── 10. Confirmation Success Response ─────│    (status: PENDING_VERIFICATION)        │ (file_key, status...)
```

## 3. Upload Security Controls

| Control                | Specification                                                  | Enforcement Mechanism                                       |
| ---------------------- | -------------------------------------------------------------- | ----------------------------------------------------------- |
| **Allowed File Types** | PDF (`application/pdf`), JPG (`image/jpeg`), PNG (`image/png`) | Magic-bytes header inspection + S3 Content-Type header lock |
| **Max File Size**      | 5 MB maximum per uploaded document                             | Enforced by pre-signed URL `Content-Length-Range` header    |
| **Storage Key Format** | `documents/{farmerId}/{year}/{UUIDv4}.{ext}`                   | Generated server-side; original filename is stripped        |
| **Antivirus Scanning** | S3 Event Trigger -> ClamAV Container Worker                    | Quarantines file if virus signature detected                |
| **Download Security**  | Pre-Signed GET URLs with **15-minute TTL**                     | Requires authenticated JWT session to request download URL  |

## 4. Database File Metadata Schema (`farmer_documents`)

```sql
CREATE TABLE farmer_documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  farmer_id UUID NOT NULL REFERENCES farmers(id) ON DELETE RESTRICT,
  document_type VARCHAR(50) NOT NULL, -- 'IDENTITY', 'LAND_RECORD', 'BANK_PASSBOOK'
  file_key VARCHAR(255) NOT NULL UNIQUE,
  file_name_original VARCHAR(255) NOT NULL,
  mime_type VARCHAR(100) NOT NULL,
  file_size_bytes BIGINT NOT NULL,
  status VARCHAR(30) NOT NULL DEFAULT 'PENDING_VERIFICATION', -- 'PENDING_VERIFICATION', 'VERIFIED', 'REJECTED'
  rejection_reason TEXT NULL,
  verified_by UUID NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```
